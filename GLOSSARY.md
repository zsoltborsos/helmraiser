# Helmraiser

Helmraiser runs coding tasks unattended through pi, checks the result against the task's own
acceptance commands, and lands it or hands it to the owner. These are the words its code,
docs, task files and directives use.

## Language

### Work

**Task**:
A unit of requested work in one project, written as a task file with a goal, an acceptance
block and optional declared paths.
_Avoid_: Job, ticket, issue

**Draft**:
A task that has not been queued yet, whoever wrote it.
_Avoid_: Proposal, todo

**Scout**:
A read-only model session that looks through a project and writes drafts.
_Avoid_: Discovery agent

**Intake**:
The step that turns a draft into a queued task, with a model proposing the acceptance block
unless the task file already has one.
_Avoid_: Triage, onboarding

**Acceptance block**:
The verify steps and evidence steps that decide whether a task's result is acceptable.
_Avoid_: Acceptance criteria, checks

**Declared paths**:
The repository paths a task may change; changes outside them fail the iteration.
_Avoid_: Scope (for the field itself), allowlist

**Origin**:
The session that queued a task and therefore owns its review.
_Avoid_: Owner session, requester

**Project notes**:
Owner-maintained lessons about a project's sandbox and conventions that Helmraiser passes to
every model working on that project.
_Avoid_: Project memory, lessons file

**Leeboard brief**:
Bounded, advisory Leeboard context generated by Helmraiser for a run's implementation
directives, distinct from project notes and scheduling Leeboard holds.
_Avoid_: project notes, hold gate

### Runs

**Run**:
One attempt at a task, from setup to its final status, in its own worktree and branch.
_Avoid_: Job, execution, attempt

**Stage**:
The part of a run in progress: setup, plan, implement, verify, evidence or review.
_Avoid_: Phase, step

**Setup**:
The project's preparation command that runs in a fresh run worktree before any model works
in it.
_Avoid_: Install, bootstrap

**Iteration**:
One implement pass followed by a check of declared paths and the verify steps.
_Avoid_: Attempt, try

**Fallback**:
The second implement model, which takes over in a fresh session when the first one cannot
finish.
_Avoid_: Escalation model, backup model

**Verify step**:
A command from the acceptance block that must pass for the run to proceed.
_Avoid_: Test step, check

**Evidence**:
Output that evidence steps collect after verify passes, for the reviewer to judge against
stated criteria.
_Avoid_: Artifacts (for the whole), proof

**Review round**:
One pass of the review model over the run's diff and evidence, possibly followed by fixes.
_Avoid_: Review cycle, review iteration

**Hint**:
A short explanation Helmraiser attaches to a known sandbox or environment failure, saying what
to change.
_Avoid_: Tip, suggestion

**Failure reason**:
The one-line cause recorded when a run fails.
_Avoid_: Error message

### Outcomes and owner actions

**Policy**:
The task's rule for how a passing run lands: `auto`, `review` or `approve-plan-first`.
_Avoid_: Approval policy; never use for sandbox settings

**Delivery**:
How a run's result reaches the project: merged into the base branch or opened as a pull
request.
_Avoid_: Publishing, shipping

**Land**:
The owner's command to take a pull-request run through CI into its base branch, distinct
from the delivered run's **Landed** status.
_Avoid_: Ship, publish

**Landed**:
The final status of a run whose result was delivered, by merge or by pull request, or
recorded as merged outside Helmraiser (**Record landed**).
_Avoid_: Succeeded, done, merged

**Awaiting approval**:
The status of a run parked for the owner's decision on a plan approval, a scope request or a
merge approval.
_Avoid_: Awaiting merge, pending, waiting

**Plan approval**:
The owner's decision on a run's plan before implementation starts.
_Avoid_: Plan review

**Scope request**:
An implementer's `SCOPE:` answer asking for files outside the task's `paths`; the run parks
until the owner approves (adding the paths to the task file), declines or rejects it.
_Avoid_: Scope violation, path request

**Decline**:
The owner's no to a scope request: paths stay unchanged and the run resumes with the note.
It does not end the run.

**Merge approval**:
The owner's decision to deliver a reviewed run, whichever delivery it uses.
_Avoid_: Landing approval, merge review

**Rework**:
The owner's action that sends a run awaiting merge approval back to implementation, with
feedback, in the same worktree.
_Avoid_: Redo, revise

**Retry**:
The owner's action that gives a failed run, once its task file is fixed, another verify or
another implementation or, when nothing was committed, a restart of the run's work in
its existing worktree.
_Avoid_: Rerun, restart

**Record landed**:
The owner's action that marks a failed or aborted run **Landed** because its branch was
merged into the base branch outside Helmraiser. Helmraiser does not verify or review that
commit; the run's `landed_outside` event says so.
_Avoid_: Force land, mark done

**Resuming**:
The status of a run handed back to the worker by a plan or scope approval, a decline, a rework or a
retry, until the worker picks it up.
_Avoid_: Handed back, requeued

**Reject**:
The owner's action that ends a waiting run (awaiting approval, or resuming before the worker
picks it up) without delivering it.
_Avoid_: Discard

**Abort**:
Stopping a run in progress before it reaches a final status.
_Avoid_: Kill, cancel

### Running the queue

**Queue**:
The ordered set of queued tasks across all projects that the worker takes runs from.
_Avoid_: Backlog, inbox

**Worker**:
The long-running process that takes tasks from the queue and runs them, several at once up
to its limits.
_Avoid_: Daemon, runner, agent

**Pause**:
A stop on starting new runs in any project, set by the owner or by Helmraiser itself; runs in
progress continue.
_Avoid_: Freeze, halt

**Hold**:
A reason a queued task is skipped for now while later tasks may start.
_Avoid_: Block, wait

**Dependency hold**:
A hold on a task until every task it depends on has landed into its base branch.
_Avoid_: Blocked task

**Project hold**:
A hold on a project's queued tasks while another run of that project uses its last run
slot.
_Avoid_: Project lock

**Leeboard hold**:
A kind of **Hold** that skips fresh queued tasks while an active, in-scope Leeboard hold
names `helmraiser-run`; project-run and dependency holds are sibling kinds.
_Avoid_: Leeboard preflight, failed task

**Provider hold**:
A period during which the worker starts no run that would use a model provider whose quota
has run out.
_Avoid_: Quota hold

**Model profile**:
The model and thinking level Helmraiser uses for one role: intake, plan, implement, fallback,
review or scout. A project's `[models]` table in `project.toml` overrides the config's
profiles for that project's tasks, and a task's `models:` overrides both.
_Avoid_: Model config, agent profile

**Budget**:
The limits on one run's cost, time and iterations.
_Avoid_: Caps, quota

**Ledger**:
The central record of every task, run and event, which all status and decisions are read
from.
_Avoid_: Database, history, log

### Isolation

**Isolation**:
The level of confinement a task's runs use: `none` or `process`.
_Avoid_: Sandbox mode, security level

**Sandbox**:
The confined environment that setup, pi sessions, verify and evidence run in under process
isolation.
_Avoid_: Container, jail

**Sandbox settings**:
What one sandboxed component may read, write and reach on the network.
_Avoid_: Sandbox policy, setup policy, policy

**Service**:
A container a project declares, such as a database, that Helmraiser starts for a run's verify
and evidence steps.
_Avoid_: Sidecar, dependency

**Preflight**:
Trying a project's setup and commands in the sandbox outside any run, to see whether they
work there.
_Avoid_: Dry run, sandbox test
